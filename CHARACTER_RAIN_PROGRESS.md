# Character construction and readable rain / working continuation

v0.5.4 Cellar Repair remains the public verified release. This is a working
continuation, not a new release or final Surveyor-art approval.

## Actual character work

The existing licensed base-character archive was inspected. It contains the same
male/female anatomical bases, with fitted hairstyle variants; no ready-made horror
antagonist was found. The CC0 licence was reread. Earlier rejected Hollow/Return
studies were not used as inputs. All isolated studies and failed logs remain in
../Builds/UNLISTED_CharacterStudy_01.

The latest study uses the existing 65-bone rig and seven animations, a sculpted
asymmetric jaw/orbits, recessed non-luminous orbital tissue, narrowed proportions,
licensed hair rebound to Head, relaxed listening angle, existing skin/canvas
textures and original vertex wear. The coat is now one weighted torso/sleeve
surface with an extruded skirt, bounded edges and a placket. Removing overlapping
old shirt faces corrected the intermediate shoulder holes. Separate chest cubes,
old hood and floating pocket blocks are absent.

This is NOT promoted to the default enemy. The face, hair and garment still read
too artificial and insufficiently authored. Mechanical tests do not approve that
appearance. Ordinary gameplay and the archive feed keep surveyor_presence.glb.
The study is available only with --surveyor-study alongside an isolated QA flag.
Editable packed source: tools/Surveyor_ErasureStudy.blend. Builder requires the
preserved Universal Base Characters Standard ZIP in the existing Assets folder.

Windows Study03 captured front/close/side views and actual live-AI pursuit,
physical contact, pause/resume, death and retry. See FinalStudyViews,
QA/capture_native and FinalStudyContact.log. No forced actor-state assertions
substitute for contact. These are automated fixtures, not a human playtest.
An early external-model Windows loader failed; a later selector type error was
fixed. Their evidence remains separate from the final imported-resource run.

## Weather implementation

The original 6,800-drop field covers nearly 7,000 square metres, so it produces
little foreground rain. An additional 1,500-drop world-space field follows the
player's area, sharing the roof-aware heightfield collision. Short fast streaks
and a small footprint supply visible rain through windows, around the porch and
in the yard without turning the whole horizon white. Existing mist, clouds,
terrain, foundations, gate, trees and wet materials remain intact. Outdoor rain
is 5 dB louder, sheltered rain 2 dB louder, with cellar attenuation retained.
This is a level adjustment, not a claim of subjective listening approval.

WeatherAfter contains 17 real Windows exterior fixtures. The kitchen view keeps
rain beyond the glass; the porch and shed views visibly show the denser field.
WeatherTraversal uses ordinary synthetic movement and actual door interactions
through the gate, lane, shed perimeter, service threshold and return approach.
Do not call capture readback FPS a gameplay performance benchmark.
